## Leads

- **A size taken from a constant, not from the box the node draws in (2 fixes): `feedback-1793905798698` (`9d6bdd9`) and `feedback-1794011769640` (`9cb98fa`).** Both are `layout-rule`, and both fixes changed the same kind of thing.
  - `9d6bdd9`: the splash took its width from `SIDEBAR_PX` (the sidebar's outer width) while drawing into its padded content box, and overshot by `2 * PAD`.
  - `9cb98fa`: the terminal's cell maths subtracted a 2 px `BODY_PAD` while the pane padded the body by `chrome::MARGIN` (12 px), so the shell was told of four more columns than fit.
  - **Structural fix, if it reaches four cases:** derive a node's usable size from its laid-out `ComputedNode` (size less `ComputedNode::padding`), not from constants that restate the padding.
  - **Guard:** for every node that converts between pixels and a count (cells, rows, thumbnails), the count times the unit fits the content box exactly.
  - **Size:** medium.
- **Terminal files are hot (2 fixes each in `terminal_pane.rs` and `terminal_view.rs`), but the mechanisms differ.** `9cb98fa` is the inset geometry above; `b7d5e79e` is keyboard chords (Cmd+V/C/A fell through as letters). One thing is shared: both are places where the new terminal assumed Linux or one convention, and a Mac contradicted it. That is a lead about the terminal's youth, not a mechanism.
- **`tiles.rs` is in two fixes (`5e2f033`, `c893709`) with different causes:** the door cue's wording, and packs folded by default. Not a pattern; the Kits door is simply where two notes landed.
- **`launcher.rs` is still at 4 fixes (unchanged).** No new launcher fix; the first review's verdict (four different causes) stands.
- **Second closings are common: 3 of 5 new lines.** A blocked row requeued by a person was fixed on its second visit every time. The `blocked` outcome has so far meant "this pass ran out", not "this cannot be done".
