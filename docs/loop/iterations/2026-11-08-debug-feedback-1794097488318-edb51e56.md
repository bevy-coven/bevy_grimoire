## The cause

gooey spells a Mac's chords with Apple's symbols unless the host says otherwise, because only the host knows which face it ships. `bevy_gooey::BindingSettings::chord_glyphs` (`ChordGlyphs::Glyphs` by default, `ChordGlyphs::Words` for a face without them) is that statement; gooey added it for `bevy_gooey#45`, in the rev this editor already pins (`04a3cdf`, and `70126ef` in 0.5.0). The editor never set it. Every place gooey draws a chord reads the one setting: a tooltip's keycap, a menu row, the shortcut badges and the palette.

## Oracle: `other:face-coverage`

"One of the characters is a `?`" is a relation between two things one build holds, the words drawn and the face they are drawn in; the face's own character map is the independent measurement (nothing here reads gooey's spelling table). The existing `capture_feedback_1793927744511` asks the same question the other way round, "does the face cover every glyph gooey can emit", and is `#[ignore]`d on a premise (a face swap) that the upstream fix did not take; it is left as it is.

Two tests, both new:

- `ui::tests::every_chord_spelled_on_a_mac_is_drawable_in_the_face_the_editor_ships` (in `src/ui.rs`, the file that holds the setting): six modifier sets (none, each of the four, all) times twelve keys (a letter, a digit, a comma, and the named keys `↩⌫⌦⎋⇥↑↓←→`), spelled as a Mac through the editor's `BindingSettings`, every codepoint looked up in the shipped face with `ttf-parser`.
- `capture_feedback_1794097488318::every_chord_the_editor_draws_on_a_mac_is_made_of_glyphs_its_face_has` (whole application, `harness::build_headless`): the headless editor is a Linux build, whose primary modifier is Ctrl, so the test sets the platform to Mac and puts the editor's own Ctrl chords as a Mac build holds them (Command), then reads **every** `ChordText` on screen and checks its codepoints against the character map of the face it is drawn in. It also requires a Command chord on `Z` to be among them, so it cannot pass by finding no keycap.

## The fix

`ui::editor_binding_settings()` returns `BindingSettings { chord_glyphs: ChordGlyphs::Words, .. }` and `EditorUiPlugin` inserts it beside the skin. On a Mac a chord reads `Cmd+Z`, `Shift+Cmd+P`, `Ctrl+Esc`; on Windows and Linux the two spellings were already the same string, so those are unchanged. One setting, no wrapper and no change in gooey. Product files: `crates/bevy_cauldron/src/ui.rs` (and a doc comment in `commands.rs` that said `⌘S`).

Passing run (`edb51e56`, on big): both tests pass (`2 tests run: 2 passed`), `cargo clippy -p bevy_cauldron --all-targets -- -D warnings` is clean.
