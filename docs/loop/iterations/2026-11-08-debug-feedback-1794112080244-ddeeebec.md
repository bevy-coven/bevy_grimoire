- **Kind: bug.** "It freezes" says how the screen is; the second sentence is what the person wants instead, and is the spec.
- **Symptom `unresponsive`:** nothing answers a key. The editor is not hung (the capture's log keeps its 600 frames per ten seconds); the pane is.
- **Cause `state-sync`:** the shell's own state, that it had left, never reached the pane. `Terminal::pump` read the PTY and treated the read error a closed slave gives (`EIO`) as the ordinary end of a drain, nothing looked at the child, the session kept it as a zombie, and the tab stayed. Leaving `omp` is not part of it: `omp` runs at the shell's prompt, and `exit` there ends the same shell.
- **Regression: none.** The one earlier `state-sync` fix (`feedback-1793927950267`, `f89e1df`) changed the selection rail in `ui.rs`; no file in common. `closing_a_terminal_never_waits_on_its_child` (#337) is the other end of the same lifetime (closing a session) and is untouched.
- **Units of `at`:** `at 246.1, 1011.5` is inside `rect_px` [0, 1006, 2560, 1405] and outside it divided by the scale factor (123.0, 505.7), so **surface pixels**.

## Oracle: `spec`

The note says what the screen should do: close this terminal, then let the person make another. That is observable state after typing `exit`: the tab is gone and the pane is the pane of nothing open (here, with an agent chosen, the `Invoke Agent` button and the `+` chip). Two tests:

- **At the level of the defect** (`terminal/tests.rs`, new functions beside the existing ones, on a real `/bin/sh` in a real PTY): `a_session_knows_when_its_shell_has_left`, `a_shell_told_to_exit_takes_its_tab_with_it`, `a_tab_that_leaves_behind_the_drawn_one_keeps_the_drawn_one_drawn` (tab 0 leaves while tab 1 is drawn; the drawn one is the same shell afterwards) and `a_shell_that_cannot_stay_up_keeps_its_tab_and_says_why`.
- **Across the application** (`capture_feedback_1794112080244`): the editor on a project that chooses a custom agent whose command prints `AGENT-UP` and returns to the prompt (as `omp` does when it is left); press `Invoke Agent`; wait for the print; type `exit`; the terminal empties, the `Invoke Agent` button comes back, none of the closed shell's rows is still drawn in the body, and the `+` chip opens a shell that is up.

## The fix

- `TerminalSession::has_exited` (`terminal/pty.rs`): `waitid` with `NOWAIT`, the look the hang-up wait already used, now one function (`child_has_left`) shared by both. It does not collect the child, so the pid stays the shell's.
- `Terminal::pump` (`terminal/mod.rs`) asks **before** it drains, so what the shell wrote on its way out is read. A shell that left after something was sent to it (`Terminal::write` now marks the tab `typed`: a key, a paste, a mouse report, the `cd` chip) has its tab removed with `remove_tab`, which also keeps the drawn tab the same one when another goes; `close_active` goes through it too. What follows is the `×` path's, unchanged: no agent chosen, a fresh shell the next frame; an agent chosen, the `Invoke Agent` button; and `+` opens another either way.
- A shell that left with nothing sent to it (a bad `terminal_shell`, an rc file that ends the session) **keeps its tab** with `the shell ended before anything was typed to it; close this tab and open another`, and an agent tab's self test says the shell stopped before the agent was typed. Closing it would open a fresh shell the next frame, for ever.

One rule decides the two: *did a person send it anything*. No timers.
