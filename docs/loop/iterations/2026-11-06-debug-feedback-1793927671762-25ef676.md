# feedback-1793927671762 — a prompt keycap's letter is not centred

**Classification:** `bug`. The note says the X **is** not centred, which is a statement about how the
thing is rather than about how it should be.

**Outcome:** `blocked` on [bevy-coven/bevy_gooey#44](https://github.com/bevy-coven/bevy_gooey/issues/44).
The cause is in the crate that lays the keycap out, and this repo must not patch, wrap or vendor a family
crate. Commit `25ef676` carries the receipt: a test that fails on the pin this repo holds.

## The relation, and why

**Alignment**: the glyph's ink against the box that holds it. Segura, Fraser, Sánchez & Ruiz-Cortés, *A
Survey on Metamorphic Testing* (`10.1109/TSE.2016.2532875`): the effective relations are those "strongly
inspired by the semantics of the program under test", and the semantics here are a *centred* label, which
the code declares itself — every keycap is spawned with `TextLayout::new(Justify::Center, LineBreak::NoWrap)`.
A keycap whose text sits off-centre contradicts its own declaration, whatever the skin's numbers are.

The survey's other finding is why this is measured rather than asserted from a constant: a relation close
to the implementation strategy — "left padding equals right padding" — **passes on this defect**, because
the padding *is* symmetric and the asymmetry arrives from `min_width`.

## Measured, from the recorded frame

```
box   x 397..440  y 252..296   (44 x 45)   centre 418.5, 274.0
ink   x 408..420  y 266..282   (13 x 17)   centre 414.0, 274.0
offset dx = -4.5 physical px (-2.25 logical)     dy = +0.0
```

y is the control: the box is not skewed as a whole, only the ink within it along the axis the row lays out.

The failing run is that output, on commit `25ef676`'s parent. Run it with:
`cargo nextest run -p bevy_cauldron --test editor -E 'test(capture_feedback_1793927671762::)' --run-ignored only`

## The cause

`bevy_gooey`, `src/skin.rs`, the `Role::PromptKey | Role::PromptButton` arm of the layout match: it sets
`min_width` on the cap — to make a one-character key a square — and never sets `justify_content` or
`align_items`, where every other centred role in that file does (lines 2889/2890, 2909/2910, 2927/2928,
3030/3031). The `min_width` widens the **node**; the text run keeps its natural width pinned to the left, so
all the slack shows on the right. `Justify::Center` centres glyphs within the text's own run, which never
grows to fill a width its parent assigned.

## What this repo did

- Filed the issue with the measurements, the cause and the acceptance.
- Set the capture `blocked` on it.
- Kept the test as the receipt, `#[ignore]`d with the issue number — not deleted (a deleted test is a
  forgotten defect), not left red (a permanently red suite teaches a loop to ignore red).
- Did **not** touch the pin, the skin, or any family crate. A pin bump is the fix, and this test is what
  will prove it.
