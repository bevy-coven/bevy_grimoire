## Summary
The audit and the registry for #198, all four acceptance items in one slice. `bevy_grimoire_core::reload::KINDS` lists 33 kinds of file the editor writes, each with a `ReloadClass` (Live, Respawn, Restart), a `Lifetime` (global, per map), its path pattern, the type it parses to and who else writes it. Every `Operation` now declares `writes()` (no default, 70 impls), so the list is enumerated from the registry. `docs/guide/reload-contract.md` is the audit, with the table rendered from the code. `reload_for` (the policy for a kind never loaded) is pure and tested here; the game-side reload does not call it yet, and H3's per-kind verdict is where it lands.

## Review
A `reviewer` subagent ran over 19bd4d2 (5 min). Its `writes()` spot check found no wrong declaration (map_rename, composition_rename, note_undo_work, destructible_*, terrain_preset, label_apply, piece_import, tree_edit, water_run and more). It found real defects, all fixed in the follow-up commit before the push:
- P2: the per-map and tree patterns were written relative to the project directory, but those files live in the authoring kit's directory (`<kit>/terrain/...`). Fixed (`<kit>/` prefix, same for `data.ron`), and the write test now dispatches `terrain_stroke` as well as `map_rename`, over the whole project root, so a wrong base fails.
- P2: `reference_images` has base Root and any file name (`references/<file>`), and nothing draws it. Fixed.
- P3: the uniqueness test filled placeholders only with `sample`; it now fills them with every literal segment of every pattern (a kit named `water` cannot make `water/library.ron` two kinds).
- P3: the restart ceiling now has to equal the list's length, so a kind cannot rejoin after another leaves without raising the number.
- P3: the `family` note claimed the game reloads it (it does not watch `<root>/family/`); `family.ron`, `agent.ron` and `play.ron` (hand-authored, read on demand) added: 33 kinds.
