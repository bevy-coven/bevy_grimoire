## The finding that unblocked the work
`Dock(DockLayout)` takes **layout data**; `PanelRegistry::register(id, title, spawn)` takes a closure; the
dock's own frame and titles come from the running `GooeySkin`. **No colour is passed in**, and the
editor's viewport is a `Handle<Image>` — an `ImageNode` inside a panel. So #210 (which replaces the
colour constants *inside* the panels) is not a gate for building the shell around them. Recorded on
#224 with the risk named: the panels keep `chrome.rs`'s colours until #210, which is the state the
series is already in everywhere. **The issue's `Depends on` line is the owner's to edit**; the loop did
not.

## Enhancement: the shell's regions are gooey dock panels (#224, slice 1)
`EditorUiPlugin` registers INSPECTOR, VIEWPORT, PLACE and STATUS at `PreStartup`; `ui::shell_layout()`
is a `DockLayout` — left dock, viewport with the most room, right dock — and `chrome::frame` spawns it
into the viewport slot, so the split beside the viewport is gooey data with a draggable divider.
**Not done:** `Frame`'s `left`/`right` stay hand-built, because **twelve systems** read those entities.

## Enhancement: the status band counts the set in hand (#228, slice 1)
A `SelectionCount` readout written from `CloneDrag::held_pieces()` — `pieces + stamps`, a stamp being a
whole tile. Empty when nothing is held, because a permanent `0 selected` is a row readers stop seeing.

## Two lessons the tests taught
- A system that watches a resource belongs in **`Update`**, not the `OnEnter` tuple it was first
  registered in, where it ran once and never again.
- `CloneDrag` clears `held` unless `state.tool == Tool::Clone`, so a test must select the tool first.
  The editor was right both times.
