# 2026-10-25 checks: every map change says what it broke, and the baseline's one red was the test

Focus: describe → set up → inspect (the agent inspects its own change) · Commits: `ae98a46`..`HEAD` of `loop/2026-10-25-checks` (`b499853` is the feature commit this report is named for; two fixes followed it) · Outcome: shipped

## Summary

`main` was red on one test. That failure was the test's own lookup — the Kit door spawns two panels
titled `INSPECTOR`, one hidden, and the helper took whichever came first in ECS order — so the fix is
in the test and the product is untouched.

The enhancement is the brief's own rule: *"Relevant validators run after every mutation. Their
failures appear in the tool result."* An agent's `emerge_apply_operation` answer now carries a
`checks` object naming the edge faults and overlapping placements **the change introduced**, with the
whole map's totals beside them. `"applied"` alone could not tell a `placement_set_yaw` that opened a
seam on the far side of a 720-placement map from one that changed nothing.

Scope is the user's: edge faults and overlaps. The two other parts of E-074 are filed rather than
half-built — **E-079** (a crate in a doorway, which `stack::blocking`'s own doc says nothing compares
across layers) and **E-080** (variety, which needs the solver grid the editor discards).

## Bugs fixed

### B-051: the labels row's panel was looked up by a title two panels share

Must-fix: blocks n (the product drew correctly), common n (one test), no workaround n — it is a test,
and a test that fails for its own reason is not a product fault. It was fixed first because the loop
contract says a red baseline is the first bug.

**Root cause: the test, not the product.** `labels_row_and_inspector_x` found its panel by taking the
first `Text == "INSPECTOR"` in ECS order. The Kit door spawns **two** panels with that exact title —
the Tiles panel (`tiles.rs`:4339) and the Anim panel (`anim_tab.rs`:343), the latter spawned
`Display::None` and left in the world — so after a door crossing's teardown the first match was
sometimes the hidden Anim title, and the assertion compared the row against a panel it never sat in.
The labels row is correctly inside the Tiles panel (`tiles.rs`:9860-9871) and always was.

**Fix:** the panel is derived from the row — the first `Ground` ancestor of the one `Text` containing
`"confidence "` — and the assertion then requires that some `INSPECTOR` title with a non-zero
`ComputedNode` has that panel among its ancestors, so a hidden panel cannot satisfy it. Zero size is
this crate's established visibility test (`tests/headless.rs`:11904-11906).

Regression check: `the_meshes_pane_says_how_sure_the_labels_are::a_long_model_stem_wraps_inside_the_inspector_and_keeps_the_confidence_first`
— `7 passed; 1 failed` at `:208` on the base commit, `8 passed` after. Measured on big.

No visuals: nothing on screen changed, by design. The claim is that the pixels were always right.

## Enhancement: every map change reports the edge faults and overlaps it introduced (E-074)

**User-facing goal:** an agent that changes a map is told what its change broke, in the answer it
already reads, without asking a second question.

**Plan:** a whole-map overlap pass in core, a `checks` module in the mapper that diffs two snapshots,
and the same two lines of wiring in **both** front ends.

**Files:** `crates/bevy_emerge_core/src/stack.rs` (`overlaps` + 3 tests),
`crates/bevy_emerge_core/src/adjacency.rs` (`dir_name` public), `crates/bevy_emerge_mapper/src/checks.rs`
(new), `ops_brp.rs`, `sequencer.rs`, `crates/bevy_emerge_mcp/{main.rs,docs.rs}` and the regenerated
`docs/mcp-tools.md`.

**MCP:** no tool added or removed; `emerge_apply_operation`'s answer gains `checks`, and its
description gains one factual sentence saying so. Undo strategy and preview are unchanged — a finding
never becomes a refusal, so `outcome` stays `"applied"`.

```json
"checks": {
  "edge_faults": {"new": [{"a": "..", "b": "..", "dir": "E", "message": ".."}], "new_total": 1, "total": 3},
  "overlaps":    {"new": [{"a": "crate@0", "b": "crate@1"}],                  "new_total": 1, "total": 1}
}
```

**Four design decisions worth stating.**

- **`new` is the difference, `total` is the map.** An agent told twenty standing faults every time it
  moves a crate learns to ignore the field, which is the same as not reporting them. A finding's
  identity is `(a, b, dir)` for an edge fault and the sorted id pair for an overlap, so a reworded
  message or a reordered file is not a change.
- **A finding is not a refusal.** The change happened; the agent decides. A validator that refused
  would be a second opinion on a rule the click path already enforces.
- **Absence and `null` mean different things.** A preview has no `checks` key at all, because it
  changed nothing and a key would claim a check ran. An operation that touches no document answers
  `"checks": null`. The test pins that difference rather than tolerating either.
- **`map_open` is named literally in `wanted`.** Every other operation is checked because the registry
  says `undo() != Undo::None`; `map_open` replaces the whole map and declares `Undo::None`, so the
  registry cannot name it — and it is the operation whose findings a reader most needs. Named, with
  the reason, rather than a second list.

`stack::overlaps` is its own function rather than `blockers` per placement: `blockers` resolves a guest
once and every other placement once per call, so asking it about each placement is n resolutions and
n² tests where this is n resolutions and the same n² tests.

**Lenses it serves.** *Agent self-inspection* — the agent can now check its own result for two of the
three objective properties the brief names, in the call that made the change. *Parity* — both front
ends answer alike, so a capture sequence and a direct apply cannot disagree about what a change broke.

**Candidates considered and not chosen**

- *Doorway clearance* (now E-079): `common: true`, but `stack::same_layer` never compares across
  layers, so it is a new rule about what an author wants refused, not a missing measurement. It does
  not fit one iteration beside this.
- *Variety measurement* (now E-080): needs `range::measure` to reach a `Map`, and `grammar::learn`
  hands the editor back only the `Grammar`. A structural adapter, not a report.
- *Updating the editor's own `EdgeFaults` panel from an agent's answer*: rejected for this iteration —
  it is a different surface (the person's, not the agent's), and coupling them would let an agent's
  change redraw a panel mid-sequence.

## Borrowed from Mixar

None this iteration. The behaviour note is the reason the shape is what it is: a turn's result is
narrated by **measured effect**, not by a log — `checks` is exactly that, the measured effect of a
change, and it is attached to the step that made it rather than to a separate query.

## Performance

`perf.py` before → after: frame 17.1 → 16.7 ms; key p95 36.3 → 34.6 ms; MCP 23.0 → 22.1 ms;
`mcp_call_ms` 36.0 → 42.4 ms; load 3.4 → 4.5.

`mcp_call_ms` times `placement_set_yaw` on Sanctuary's 720-placement `town` map, so it includes the
checks **twice** (before and after the dispatch). **+6.4 ms** for two whole-map passes over 720
placements and 781 overlaps. A second sample at load 4.9 read 60.4 ms and a third 42.4 ms; the laptop's
load moved between 3.3 and 10.5 across runs, so the honest reading is "a few milliseconds to about
twenty, on the worst map in the project". No profiling was done because nothing needed it: the n² part
is separating-axis tests over resolved rectangles, and it sits under 10 ms on the largest map in the
repo.

**`file_ms` is not usable this iteration.** The before run read 84.4 ms; the after run read 227.2 ms on
a run whose load was 9.3 and then `null` on the next two (`perf.py` reported `file_ms: null`, the
latency poll coming back empty). That is the harness timing out under load, not a regression in a path
this change does not touch — the file path goes through the watcher and never calls `checks`. It is
reported as unmeasured rather than as a number.

## Live proof on a real map

One `placement_set_yaw` on Sanctuary's `town` through the running editor and the MCP server, on a
scratch copy:

```
scratch: /tmp/emerge_probe/run-1792958440 load: 39.2
outcome: applied
checks: {
  "edge_faults": {"new": [], "new_total": 0, "total": 0},
  "overlaps":    {"new": [], "new_total": 0, "total": 781}
}
```

**781.** That number is not the feature's opinion, so it was cross-checked against the rule the editor
already enforces: for each pair, take one placement out of the map and ask `stack::blockers` — the
click path's own function — whether the other is among what it would refuse. It agreed on **781 of
781, 0 disagreements**. Sanctuary's town map holds 781 interpenetrating pairs that nothing could see
before this; they are pre-existing authoring (fences through fields, roads through houses, towers
through wall segments), and `new_total: 0` says this change made none of them.

That is the argument for the field: the map has been carrying 781 invisible overlaps and every tool
answer said "applied".

## Review

An independent reviewer read `git diff main...loop/2026-10-25-checks` against this iteration's
context and returned a severity table.

**One real bug was found by this iteration's own self-review, before the reviewer reported**, and is
fixed in its own commit (`ce10175`): `map_open` takes its `before` from the map it is about to
replace, and findings are matched by placement **id** — which every map of a kit shares (`wall@0`,
`pane@1`). Opening map B therefore compared B's faults against an unrelated piece of the same id in
map A and reported a real fault as *nothing new*. `Found` now carries its map and `report` discards a
`before` from a different one. Fails without the guard (`new_total` 0 where 1 is right), passes with it.

Reviewer findings, and what was done with each:

| Severity | Finding | Outcome |
|---|---|---|
| **BLOCK** | `map_rename` reported every standing finding as new — the path guard added in `ce10175` compared `OpenMap::map_path`, and a rename keeps the document and repoints the path. Renaming Sanctuary's `town` would have answered `new_total: 781`. | **Fixed.** The rule is the operation's own: `map_open` replaces the map, nothing else does. One function (`checks::before`) answers it and both front ends call it. Regression test `a_rename_reports_nothing_as_new`, which fails on `ce10175` and passes after. |
| MINOR | E-079's evidence cited `descriptor.rs:667`, whose ruling is about `solid`, and the same passage says `clearance` *does* decide space. | **Fixed.** The claim was true (nothing in `stack.rs` reads `clearance`; its only readers are validation and the composition hash) and the citation now says so, with the grep that shows it. |
| MINOR | This report pointed at a "Review outcome" section that does not exist. | **Fixed** — this table. |
| MINOR | The report's commit range and its gate claim predated two commits. | **Fixed**: the range above, and the gate was re-run after both. |

The reviewer also confirmed, independently and in the areas it was asked to prioritise: `overlaps`
