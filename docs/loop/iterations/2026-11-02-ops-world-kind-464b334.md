## Enhancement: `Change::World`
Goal: name why `Undo` cannot be an operation today. · Files: `keys.rs` (the kind and thirteen arms), the
classification test (its pinned set and the coverage arithmetic).
Proof: parity **9/9**; full editor suite **1154 passed, 0 failed**; clippy clean; gate passed in 190 s.

**The gap this exposes is the largest in the surface.** An agent driving the editor over MCP can place,
remove, turn, pin and save a map — and **it cannot undo**. `editor::undo` takes seven parameters, three of
them ECS (`Commands`, `AssetServer`, two `Query`s). No re-classification fixes that.

Two ways to close it, recommended on the kind itself:
1. **`Ctx::deferred`** — the operation fills in *what* to undo and the front end applies it in the same
   frame, the shape `layout_propose` / `layout_accept` already use for a proposal. Reversible, keeps `Ctx`
   lifetime-free, leaves the stack where it lives.
2. **Let an operation borrow the World** — honest, and it destroys the `dyn` registry's shape for every
   operation there is.

Not built this pass: it is a change to the one trait every operation implements, and it wants its own
failing-first test (`an agent's undo and a person's Cmd+Z are one stack`).
