# feedback-1793969010186 — the sidebar's Settings cannot be clicked

**Classification:** `bug`. *"I can't click on "Settings"? It's like it's not a button"* reports how the screen
behaves.

**Outcome:** `blocked` — **reproduced with a real picking click**, cause narrowed to "the press does not reach
the button", not fixed. The pass hit 40 minutes with the fix unproven and did not push it.

| pick | the whole sidebar pane, `[0, 0, 576, 1604]` physical — **not** the chip |

**Units.** `at` = `274.9, 1180.1` surface and `137.4, 590.1` logical both fall inside the pick. **Ambiguous** →
clicks were made in logical. But the pick's own rect is the tell: a person pressing `Settings` produced a
selection of the pane *behind* it, which is what "it's not a button" looks like from the inside.

## Reproduced

`capture_feedback_1793969010186` builds the project page with the real plugins and presses the chip with
`bevy_gooey::testing::click` — the picking path a mouse uses, **not** `Activate`, because "can the person
reach it" is a different question from "is the handler wired". It fails on unmodified product code:

```
clicking the sidebar's Settings left it closed
```

## What is ruled out

| hypothesis | how it was tested | result |
|---|---|---|
| the handler is not wired | `write_message(OpenSettings)` on the same screen | **opens the dialog** — handler and dialog are fine |
| the chip is not laid out | `ComputedNode` on the button | 260 x 28 at centre (144, 657) physical — a real box |
| an ancestor swallows the press | walked six ancestors | every one is a plain `Node`; only the root is `Pickable`, and it is *behind* |
| the `Text` child eats the hit | marked it `Pickable::IGNORE` in `chrome::button` | **still fails** — not the cause |
| the widget lookup is wrong | `find_by_label` returns the `Text` when there is no `TabIndex` ancestor | **a real trap**: the first version of this test clicked the label. It walks to the `Button` now |

That last row is worth carrying: `find_by_label` resolves a widget through a `TabIndex` ancestor and **falls
back to the `Text` entity**, and these sidebar chips carry no `TabIndex` — so a test that clicks what it
returns clicks a label that has no observer. The launcher's project cards carry `TabIndex`; the sidebar chips
do not.

## Not fixed, and why

At 40 minutes the fix was not proven, and the rule is explicit: do not push it. Two candidate changes were
tried and neither worked (`Pickable::IGNORE` on the button's text; an early theory that the message had no
reader), both reverted.

**The one measurement not yet taken** is the decisive one: which entity `bevy_picking` reports as the hit for
that centre — `Pointer` hits, or `Hovered` per entity after moving the cursor there. Everything above is
inference about pickability; that is the observation.

## What this repo did
