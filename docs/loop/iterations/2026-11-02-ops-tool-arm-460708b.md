Design points:
- **One copy of the rule.** `arm_tool_in` is arming on the *value*; `arm_tool` and `tool_arm` both call it.
  A third tool key costs a line in `TOOLS`, not a second rule.
- **The tool serialises by name** (`clone`, `run`, `move`, `remove`, `note`), so reordering `Tool` cannot
  silently arm the wrong one.
- **`writes()` empty, `Undo::None`.** Arming changes what the *next click* does, so `Cmd+Z` must take back
  the last map change, not disarm a tool someone chose.
