# 2026-11-05 feedback-1793905912313: the What's new page's bottom, and the queue that found it

Capture `feedback-1793905912313`, filed 2026-11-05 13:12 on `mac_air` against Cauldron 0.2.6:
*"This has no scroll to it, so the bottom gets cut off and is not visible."* Classified `bug`, the
oldest of the four bugs by `taken_at_ms`? No — the fourth of four; `next` chose it here because the
three older bugs need a Mac and a longer look, and this one is the plan's cheapest end-to-end proof.

## What the capture shows

`window.physical` 2560 x 1406 at `scale_factor` 2.0 (`logical` 1280 x 703), `ui_scale` 2.4, screen
`launcher`, one pick on the What's new page's `Surface(0)` at `rect_px [576, 0, 2560, 1406]`. The frame
ends mid-entry at the window's edge: ten entries are listed, the third is cut, no scrollbar is drawn,
and "See every change" is nowhere. That is the note exactly.

## The cause

`launcher::fill_the_home` spawned the What's new page as a plain `flex_direction: Column` node with
`HomePage(HomeTab::WhatsNew)` and nothing that scrolls. The Projects page beside it has always wrapped
its grid in `chrome::scroll_list`; this page did not. Every entry the page lists past the first three
was therefore drawn below the window with no way to reach it — not a clipped row, an unreachable one.

## The fix

`crates/bevy_cauldron/src/launcher.rs`: the page now owns a `chrome::scroll_list` viewport
(`NewsScroll`) and draws its entries inside it, the same way the Projects grid does. `scroll_list`
brings gooey's `ScrollArea` and its bar, and the bar shows itself only when there is somewhere to go —
so a window with room to spare looks exactly as it did.

- `HomePage` and `NEWS_SHOWN` became `pub`, and the viewport carries a new `NewsScroll` marker, so a
  test can name the page and the box it scrolls in rather than guessing at a tree shape.

`crates/bevy_cauldron/tests/capture_feedback_1793905912313.rs` (one `mod` line in `all.rs`), at the
capture's own window: 1280 x 703 texels at the harness's `UiScale` 1.2, which is the same design the
person saw (their 2560 physical at `scale_factor` 2.0). Ten entries with their sentences, and the
`ScrollAreaPlugin` **asserted present** rather than added, so the test cannot pass by bringing the
plumbing it is meant to check.

The failing-first direction was run three times, the last two on the exact test text that shipped:
`git stash` of the launcher change, `cargo nextest run -p bevy_cauldron --test editor -E
'test(capture_feedback_1793905912313::)'`, then restore.

22 launcher, home and project-page tests also pass with the change, run as
`-E 'test(the_launcher_) or test(the_home_) or test(a_first_run)'`.

## What this cost, and the two mistakes worth recording

1. **The first three versions of the test measured the wrong node.** `HomePage` is content-sized and
   never clips, so a rect comparison against it proves nothing; a `UiScale` of 2.4 on a 2560-wide
   surface put gooey's split minimums in conflict and panicked `min > max` inside `split_clamp`; and
   after the fix the viewport is *inside* the page, so an ancestor-only search could not see it. What
   settled it was dumping the actual node chain and the entries' rects once, instead of guessing three
   times.
2. **A "content taller than its box" assertion could not work here.** Bevy compresses a
   `min_height: 0` column's children, so the harness reports the page's rows as fitting whether or not
   they are drawn past the window. The relation that holds in both builds is the behavioural one — is
   there a scroll, and does it reach the last row — and that is what the tests assert.
