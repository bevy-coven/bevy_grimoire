## Bugs fixed
### B-021 (#182): a click on the chrome around the viewport placed the armed piece far off the map, unseen
Must-fix: blocks n, common y, no workaround y. Common, because the door strip, the bars and the status band are clicked all the time. No workaround, because the piece lands off screen and the person never sees it to undo it.
Root cause: the map camera's viewport is the frame's hole (`surface::fit_viewport_to_frame`). But `view::cursor_ray` handed every pointer to `Camera::viewport_to_world`, and that function does not check that its point lies inside the viewport. bevy_camera 0.20's `viewport_to_ndc` extrapolates past the edge. So a pointer over chrome that carries no `Hovered` produced a ray through a pixel that does not exist. Just above the top edge, that ray meets the ground far away, which is B-021's `(-1965.65, -98.65)`.
Fix: `cursor_ray` now answers `None` outside `camera.logical_viewport_rect()`. Every caller already treats `None` as "no ground under the pointer".
Regression check: `a_click_outside_the_viewport_places_nothing::a_click_above_or_below_the_viewport_places_nothing_and_one_inside_still_places`. Before the fix it failed with "a click above (the door strip) the viewport Rect { min: (453, 72), max: (957, 689) }, at (705, 66), placed [("wall@1", (-20.5, -20.5))]". It passes after, together with the 41 pointer, removal, note and Shift-click tests.
