## The gap, in one line

`scan`'s first look (`tiles.rs`, "On the first look, only the packs THIS MAP builds from are open"):

```rust
if !state.scanned {
    let used = packs_the_kit_draws_from(project);
    state.folded_packs = packs(&found)
        .into_iter()
        .map(|(pack, _)| pack)
        .filter(|pack| !used.contains(pack.as_str()))
        .collect();
}
```

Every pack the kit **draws from** starts **open**; the rest start folded. That is the inverse of the note.
On the Kits door — whose whole subject is one kit — "draws from" covers most of the shelf, so the first look
is the whole list: the capture has nine rows under `APPLIANCE` and six under `BED`, in a panel with no room
left for anything else.

## The spec

1. **After the first scan, every pack is folded**, except —
2. **the pack holding the current selection**, which stays open, or the first look has a highlight on a row
   nobody can see.

That exception is the whole difficulty, and it is why this is not a one-character change: `scan` already has
a comment saying the default selection must be a row the author can **see**, and the fold set is computed
before `state.selected` is settled.

## Why it is blocked rather than shipped

- The unit test I wrote at the level of the defect (`pack_fold_tests`) **passes on the base commit**, because
  it pins today's rule. It is the receipt — the change the capture asks for must edit that expectation on
  purpose — but per §6 a test that does not fail is not a proof, so it was reverted rather than committed.
- The whole-application test needs a fixture kit with several packs on disk; the harness fixture's kit has
  no meshes, so the candidate list is empty and the test can only fail on its own vacuity guard.
- Building the real change needs the selection/fold ordering resolved first, which is more than the pass had
  left.
