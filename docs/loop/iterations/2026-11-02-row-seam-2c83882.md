The series is blocked behind **#210** (19 issues wait on #224, which waits on #210), and #210's
acceptance needs `chrome.rs` to declare no colour constants: **332 references across 28 constants**.
`const` cannot read a resource, so that is a refactor of every drawing system — one group a pass, not

through, so a theme edit now reaches the row a person's pointer is on.

## Enhancement: `RowFills`, the seam (#210)
`style_list_rows` keys on `RowRest`, so **every row spawned by any tab is painted there** — one system,
the whole editor's lists. It reads `GooeySkin` now through `RowFills::of(skin)`, a single expression the
system and a test share.

**A fact that cost three attempts, and is worth more than the code:** `Hovered` is bevy's **`Immutable`**
picking component. Only the picker may write it, and a headless app has none — a value inserted by the
test read back as `row hovered Some(false)`. A hovered-row assertion is therefore asking for a state a
test cannot create. What is asserted instead is the expression the system paints from, which catches
the failure that matters: `hover` read from `chrome::ROW_HOVER` rather than the skin.

**Failed before, and how:** on the base the test does not compile (`row_fills` is new) — a compile-fail,
not an assert-fail. With the change both cases pass in 0.15 s, and `chrome_census`'s 8 tests still pass.

**Not done:** 131 colour sites outside `chrome.rs` still read the constants, and `selected` has no gooey
role (`RowFills` keeps `ROW_SELECTED` and says so). The issue's acceptance stays open.
