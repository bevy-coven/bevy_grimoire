# 2026-11-01 reload: what points at a piece follows it when a live reload draws it again (#201 slice 3)

Focus: hot reload H4 (#201) · Commits: 20670d4, f07b70c (release) · Machine: laptop (edit, review) + big (build, gate, release) · Outcome: shipped

## Summary
A person a game spawns is not a placement, so a reload never draws them and their position and ties survive any edit to a piece. But a person names pieces (a society's `Home(entity)`, a list of bound places), and a piece an edit draws again has a new entity, so every such reference named an entity that was gone. A game now registers how a kind of reference reads the entity it names, once, on the app: `GrimoireLiveApp::follow_respawn::<C>(|c, respawned| c.0 = respawned.follow(c.0))`. The remaining items of #201 are the in-place split (owner), the explicit alias (deferred, assumed decision on the issue) and a society that runs inside the editor.

## Enhancement: reference hooks (build step 4 of #201, the other half)
Goal: what names a piece follows the piece when a reload draws it again, through one hook per kind of reference.
Files: `crates/bevy_grimoire/src/live.rs` (`Respawned`, `GrimoireLiveApp::follow_respawn`, `ReloadMigrations { pieces, references }`, the queued command in `reload`), `crates/bevy_grimoire/tests/live_references.rs`, `docs/guide/reload-contract.md`, `docs/guide/your-game.md`.
Proof: `live_references.rs` did not compile on the base commit on big (E0599, no `follow_respawn`, 3 sites); 4 pass after, and the rest of the workspace passes in the gate (`cargo test --workspace`, 611 s). Clippy `-D warnings` over all targets of `bevy_grimoire`: clean.
Design: the closure runs once per reload, after the per-piece hooks, in the same queued command that runs them, so every `C` sees the new entity alive and the old one still alive. `Respawned::follow(e)` answers the new entity for an old one in a pair (a piece drawn again, a rider drawn again with its host, a renamed piece drawn again) and `e` for everything else. A `C` is marked changed only when `follow` answered with another entity (`bypass_change_detection`, then `set_changed`), so a rewrite that changed nothing wakes nothing. A closure and not `MapEntities`: `bevy_society::Home(pub Entity)` has no impl and a game cannot write one (orphan rule).
Tests: unrelated edit leaves people, ties, homes alone and flags nothing; a moved house gives its tenant the new entity, the lamp on it is followed in a list of places, position and ties do not change, and only the rewritten reference is flagged; a rename keeps the entity (no rewrite) and a later change of kind is followed; a reference to a removed piece is not invented and a kind of reference nobody registered is left as it was.
