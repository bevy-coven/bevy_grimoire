# 2026-11-01 reload: a renamed placement keeps its entity across a live reload (#201 slice 1)

Focus: hot reload H4 (#201) · Commits: d0c9f1a, 8200398, c7f2c8f (release) · Machine: laptop (edit, review) + big (build, gate, release, accept) · Outcome: shipped

## Summary
The game-side `GrimoireLivePlugin` read a placement whose id changed and whose row did not as one removal and one addition, so its entity was despawned and whatever a game hung on it was lost. `diff_maps_renaming` now finds that rename by content (unambiguous pairs only, in rounds so riders on a renamed host follow), and the plugin keeps the entity and retags its `Placement`. #201 stays open: people, a rename together with an edit, a renamed map.

## Enhancement: runtime state keeps its identity across a reload (H4, slice 1)
Goal: an edit that does not change a placement does not draw it again, and a rename is not a change.
Files: `crates/bevy_grimoire_core/src/live.rs` (`diff_maps_renaming`, `MapDiff::renamed`, `same_but_id`, `renames`), `crates/bevy_grimoire/src/live.rs` (`plan` takes the renames, `reload` retags kept entities), docs/guide/reload-contract.md (new section), docs/guide/your-game.md.
Proof: `crates/bevy_grimoire/tests/live_identity.rs` (6) fails 2 on origin/main (`the rename follows the same Entity`, left 46v0 right 43v0; `the host follows its rename`) and passes 6; `crates/bevy_grimoire_core/tests/live_diff_renames.rs` (9) does not compile on origin/main (no field `renamed`). `cargo test -p bevy_grimoire_core -p bevy_grimoire` whole and `clippy -D warnings` clean on big.
Assumed decision (on #201): content inference over a schema alias, because an existing test pins `diff_maps` to take an id for the piece, and an explicit alias costs a `MAP_VERSION` bump and about 150 `Placed` literals. It is recorded on #201 with the options.
Acceptance of #201 met: 2 (rename keeps state, placements only), 3 (a reload with no change draws nothing, counted), 4 (a changed kind draws that piece only). Not met: 1 (people).
