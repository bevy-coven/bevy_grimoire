# 2026-11-01 reload: a game's data file that no longer reads is named with its file and leaf (#200 H3 slice 10)

Focus: #200 (hot reload H3, the owner's override) · Commits: ace7b65 (+ this report's commit, release 63b46b4) · Machine: laptop (edit, commit) + big (build, test, gate, release) · Outcome: shipped (the issue stays open)

## Summary
`<grimoire>/<kit>/data.ron` registers the tuning files a game owns and bounds the leaves the editor tunes. Nothing applies them to a running game (the registry classes them `Restart`), so a hand edit that stopped reading (a save cut off, a bounded leaf that became a word or went missing) cost the Data panel its rows with no word, `data_set` refused a file that did not scan without naming it, and an edit that did read was never said to be waiting for a restart. Core gains `data_files::read` (one reader; a refusal names the file and, for a cut-off file, the leaf where reading stopped) and `data_files::check` (every leaf the registry bounds must be there, a number and inside its bounds, each refused by its path); the editor's `data_view::sync_data_view` decides into `grimoire_state.reloads` as kind `game_data` per file and kind `data_registry`, and `data_set` refuses through the same reader.
