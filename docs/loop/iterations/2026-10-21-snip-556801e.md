## Enhancement: snip (`556801e`)
Problem: an agent that needs one region of the editor takes the whole window (2560 × 1406) and crops by eye. The picture is the expensive part and most of it is not the thing asked about.
Change: MCP tool `emerge_snip { label, rect: [x0, y0, x1, y1] }`, window pixels, origin top left, x1/y1 exclusive. It takes the picture the way `emerge_capture_still` does, cuts the rectangle with the `image` crate (already a workspace dependency; no new crate in the graph), writes `target/loop/captures/<label>/snip-<stamp>.png`, and returns the crop, the path, the picture size, the crop size and the state dump. An empty, reversed, negative or outside rectangle is refused and the refusal names the picture size, before any file is written. The label goes through the same check as the bug fix above.
Not an operation: changes no map, not logged, annotations match `emerge_capture_still` (writes a file, so not read-only).
Files: `crates/bevy_emerge_mcp/src/snip.rs` (new: `crop_png`), `src/main.rs` (`snip` tool, `SnipParams`, `base64_encode` helper), `src/docs.rs` (ToolDoc and schema), `src/lib.rs`, `Cargo.toml` and `Cargo.lock` (`image.workspace = true`), `tests/an_agent_calls_the_server.rs`, `docs/mcp-tools.md` (regenerated with `--emit-docs`).

Failing-before test: `the_snip_tool_says_what_it_crops_and_refuses_without_an_editor` (integration). Before the change `emerge_snip` is not listed, so it fails at the listing. After: the schema and annotations are checked, a call with no editor is a refusal naming the editor, and a `../escape` label is refused with "not a capture label".
Unit tests in `snip.rs`: crop placement, refusals naming the size, non-PNG bytes refused, a rectangle touching the far edge accepted (`[0,0,16,10]` and `[15,9,16,10]`). Total for the feature: 4 snip unit, 1 snip integration; the workspace went 1376 → 1384 with the label tests.

Naming differs from the plan: the plan named `the_snip_tool_says_what_it_crops_and_refuses_a_bad_rect` and a `snip_rect` helper. The test was renamed after review because the no-editor case was what it checked; the bad-rectangle refusal is verified with a live editor (below), not in an automated tool test. The helper is `crop_png`.
Test expectation correction: `readOnlyHint` was asserted `true` first; it passed before the implementation, so the assertion was changed to `false` to match `emerge_capture_still`. Disclosed, not hidden.
