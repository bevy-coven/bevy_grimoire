## Bugs fixed

### B-034: the palette-filter test pressed the macOS command chord on Linux
Must-fix: blocks yes, common yes, no workaround yes — every Linux CI run failed on it; main run 39811701910 (head e643327) failed on `the_map_tabs_palette_filter_takes_the_keyboard` at `crates/bevy_emerge_mapper/tests/a_run_lays_a_line_of_pieces.rs:257`.
Fix: the test pressed `KeyCode::SuperLeft`. `keys.rs` sets `MOD_KEYS` to Super on macOS and Control elsewhere, so on Linux the press was a bare `F` and `focus_filter` in `tiles.rs` never fired. The test now presses `MOD_KEYS[0]`, as `tests/headless.rs` does. Commit 13c7a5f. Root cause: a test bug, not an editor bug.
Regression check: `the_map_tabs_palette_filter_takes_the_keyboard` (the failing-before run used a probe copy of the old key press, `ci_probe_old_filter.rs`: it panics at line 257, `left: None`, `right: Some(Palette)`; the fixed test passes 4/4 — `target/loop/2026-10-22-ci-filter/flip-old.txt`, `flip-new.txt`).
Linux result for the fix: not yet observed. Run 39842732867 on 360b9af is queued.

### B-028: a rename whose old file cannot be removed reports refused but has already renamed the map
Must-fix: judgments disagreed (finisher: blocks yes, common no, workaround yes; main: blocks no). Per the brief it is must-fix only if reproduced; it was reproduced. Recorded in the backlog with both judgments.
Fix: `project.rs` `OpenMap::save`. If the old file cannot be removed, the new file is taken back, so the refusal changes nothing and the map keeps its old name. If that take-back also fails, the map follows the new file and the refusal says so. Commit 0a7ee4e.
Regression check: `crates/bevy_emerge_mapper/tests/a_rename_whose_old_file_cannot_go_changes_nothing.rs` (new, 115 lines). Failed before on `held name == "m"`; passes after (`target/loop/2026-10-22-ci-filter/b028-failing.txt`, `b028-fixed.txt`; reproduction in `b028-probe.txt`).
