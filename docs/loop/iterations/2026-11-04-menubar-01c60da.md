## Enhancement: the menu bar
Goal: every registry command in exactly one menu. Files: `crates/bevy_cauldron/src/menu_bar.rs` (new),
`editor.rs` (one `add_plugins`), `lib.rs`, `tests/the_menu_bar_holds_every_command.rs`.
A menu **is** a category; rows are the commands whose id starts with it, so a new command appears and none
appears twice. Rows show `Command::shortcut_in` (the settings' chord), a refused row is `Disabled` with the
registry's own reason, and choosing a row queues that chord through the same `Chords` queue the toolbar uses.
Proof: `a_disabled_row_carries_its_reason` failed before the fix with *CompositionPrev says None and the
registry says Some("Only while picking a composition")*.

Two interface-wide constraints, both found by running it: a menu opens as a gooey **modal popover** (a
`Dialog`), so the bar must stand down only for the editor's own question (`Confirm::is_open`) — the first
version stood down for any dialog and the bar vanished when a menu opened, which the clip showed; and a
title's words are retagged `ControlText`, because two existing tests count every `Role::ButtonText` in the
world. The second is a gooey gap: filed as `bevy-coven/bevy_gooey#39`.
