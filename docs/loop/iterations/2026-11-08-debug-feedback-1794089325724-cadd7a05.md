## Current behaviour (what the spec starts from)

The app asks the releases feed **once**, at launch (`start_the_first_check`). The launcher shows the version line (`v… · up to date` once that check found nothing) and an `Update to v…` button only while there is an offer. `update::on_activate` already begins a manual check when pressed from `UpToDate`, `Idle` or `Failed`, and a manual check that finds nothing says which version is newest. Nothing on the home reached it from `UpToDate`, so a release published after the app opened could not be found without quitting.

## Oracle: `spec`

The behaviour the note asks for, as observable state: an up-to-date home offers `Check for updates` and still no `Update to …` button; pressing it asks the feed again (a loopback feed whose body the test changes); an update published in between is then offered; a check that finds nothing says which version is newest; an app that cannot update where it is says why instead of looking.
