# feedback-1794011769640 — the terminal widened without end under omp (fixed)

Note: *"I went into OhMyPi here and the screen started stretching to the right without stopping."* Kind `bug`: it says how the screen is. The owner reported the caret out of line with typed text (on `Let's`) a few minutes earlier, against the same build. That report has the same cause, so its oracle is in this capture's test file.

- **Symptom `layout`**: the pane grew past the window, and pushed the status bar's end and the terminal's close button off it.
- **Cause `layout-rule`**: the body's padding put the rows `chrome::MARGIN` (12 logical px) in from each side. Every body/cell conversion used `BODY_PAD` (2 px).
- **Regression decision: none.** No earlier fixed case has this cause in these files. The one other `text-measure` case, feedback-1793905698793, is launcher prose, so it is not even a shared cause.
- **Diagnosis.** The pass first suspected the cell measurement: a glyph's `position` is its ink centre, so two letters' centres are not exactly one advance apart. The capture test disproved it. The measured cell was 5.999997 logical px, the face's 6.0, and the failure was unchanged with a pen-based measurement. That change was set aside; it is no part of this commit.

- **`at`:** (1335.3, 1222.9) lies inside `rect_px` [0, 944, 2607, 1344] but not inside `rect_px ÷ 2`, so it is in **surface pixels**. No click was needed.

Attempts (one; the matrix stopped at its first row):

- mac_air, metal, 2560x1406, ui_scale 2.4, **reproduced**. A throwaway driver ran a scratch HOME and a scratch copy of the bedroom project. Over 17 s the body grew from 2560 to 3774 px and the shell's columns climbed from 177 to 267.

## Oracle

`containment`. Two assertions: a rule as wide as the terminal says it is lies inside the body, and the body lies inside the window. The column count must also hold still across redraws. The caret report gets its own assertion in the same file: the caret's left edge is where its column is drawn.

## Runs

Before, on 9cb98fa's parent, all three fail:

- **`terminal_pane::tests::a_press_on_a_character_is_on_that_characters_cell`:** `left: Some((2, 6)) right: Some((2, 4))`.
- **`capture_feedback_1794011769640::a_rule_as_wide_as_the_terminal_says_stays_inside_it`:** "the terminal's body ends at x = 2607 px, past the window's edge at 2560". Per redraw, as (cols, body right, rule right): `[(177, 2607, 2578), (180, 2650, 2621), … (198, 2910, 2881)]`. 2607 is the capture's own `rect_px` right edge.
- **`capture_feedback_1794011769640::the_caret_is_on_the_cell_its_column_is_drawn_at`:** "the row draws at x = 317.00003 px; the caret is at x = 293 px, -1.7 cells off". This matches the owner's still.

After, all three pass. Clippy over `bevy_cauldron --all-targets` is clean. The terminal tests pass: 22 in the library, 58 in the editor binary.

Two existing tests pinned the old origin:

- `columns_and_body` expected `(body.x - 4.0) / cell`;
- `hit_at` built its click from the body's corner.

The owner approved correcting both in the session, so each now reads the inset from the body's resolved `ComputedNode::padding`. That change is its own commit, 5dbea0a `evaluator: … (owner-approved)`.

## Fix

`terminal_view::BODY_INSET` (MARGIN across, 2 down) is the one inset: the pane's padding, `resize_the_terminal`, the caret's left and top, the find box and `cell_under` all read it. Commit 9cb98fa. Gate passed on a2c6dca: 3,087 tests, 283 s.
