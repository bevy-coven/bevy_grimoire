# 2026-10-24 labels: an effects write says when the vocabulary overruled it (E-064)

Focus: bug sweep (all GitHub issues closed) · Commits: `f7d834d`..`f4e5fb9` · Outcome: shipped

## Summary

`set_axis` settles `effects` after an `effects` write as well as after a `kind` write, because the
derived half is the vocabulary's to state. So an author who asks to remove an implied effect has it
put back — and the receipt named only the net change, reading like the removal had happened. It now
says which effect was kept and why. The review then found that the clause could itself be wrong on a
row the file had not caught up with, and this report covers both.

## Baseline

Gate: green before and after (clippy clean; `cargo test --workspace` green). Frame time and latency
were not re-measured: the change is a `Vec` compare and a `format!` per label write.

## Enhancement: the receipt names what the vocabulary kept

Plan: capture the requested list before `set_axis` consumes it, and when an `effects` write leaves a
token out that the kind implies, say so. Files: `crates/bevy_emerge_mapper/src/ops.rs`
(`label_set`'s `edit`). Goal: a person who removes an implied effect is told the vocabulary kept it,
instead of reading a receipt that reports a removal which did not happen. Proof:
`a_label_set_on_effects_settles_as_the_kind_does.rs::an_effects_write_says_which_effect_the_vocabulary_put_back`
— fails before with `set effects on `bench`  -inert`, passes after.

| Case | Receipt |
|---|---|
| effects write that drops an implied token | `set effects on \`town/brazier\` — kept emit (the kind implies it)` |
| effects write with nothing implied | unchanged — the axis phrase alone, no "kept" |
| effects write refused (a derived token the kind does not imply) | unchanged — refusal, nothing written |
| `kind` write | unchanged — `+light; effects +emit`, as E-063 shipped it |

**Why the net phrase could not carry this.** `-inert` is true whether or not `powered` survived. The
fact that a request was overruled is not a delta — it has to be said, and it has to name the tokens
asked for and kept, which is the part nobody expected.

## The review's gap, and the fix

The first version computed the kept tokens by comparing the **raw stored** effects (`read_list`)
against the request. That is wrong on a row the file has not caught up with: `Project::open` settles
the layered `library` but **not `measured`** (`project.rs:251-255`), and `measured` is the copy this
operation edits. On such a row the screen shows `[inert, powered]` while the file holds `[inert]`, and
the receipt read:

```
set effects on `bench` +powered  -inert
```

— reporting the vocabulary's own effect as the author's **addition**. Reproduced on this change's own
fixture, and fixed by taking `effects_were` (settled) as the effects axis's "as it was", the same
argument E-063 already made for the kind axis.

Its P3 note — `tokens.clone()` ran on every write and was then dropped — is also taken:
`(axis == "effects").then(|| tokens.clone())`.
