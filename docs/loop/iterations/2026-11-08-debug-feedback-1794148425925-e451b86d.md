## What was built

omp has the flag (`omp --resume <id>`, which takes an id prefix) and an extension API; it has no way to print the id it is in. So:

- **The extension Cauldron writes beside the MCP config on every launch** (`terminal_agent::OMP_EXTENSION_SOURCE`, which was an empty extension) now tells the editor which session its tab is in: on `session_start` and `session_switch` it reads `ctx.sessionManager.getSessionId()` and posts `grimoire/agent_session {token, session}` to the editor's own BRP port (both in the shell's environment already); on `session_shutdown` it posts `session: null`. A post the editor cannot take is said in omp's own UI. **Verified against the real omp** (v18.18.0) on mac_air with a stand-in BRP server: the extension, extracted from the Rust constant, posted `{"token":"smoketoken","session":"01a1bc84-…"}` at start and `…"session":null` at shutdown. The scratch sessions that run made were removed. A second run with `--resume <id prefix>` started in the same session id.
- **`agent_resume.rs`**: one file per person, `<data dir>/agents/resume.json`, one entry per project (`project`, `harness`, `session`), atomic writes, a damaged or unknown-version file refused and left alone.
- **`terminal_agent::keep_the_resume_record`** writes the entry when a tab reports a session and strikes it out when the agent leaves its session (`null`), when its tab is removed (`Terminal::remove_tab`, which the person's close and a typed `exit` both reach), and when a resumed omp never connects within the 60 s (`AgentPost::resume_failed`). **Nothing runs at editor quit**, which is what makes a surviving entry "an agent that was running when it closed". An error from the file is said in the pane's refusal.
- **`terminal_pane::resume_the_agent_that_was_running`**: once per project per run, on the first frame the terminal would offer Invoke Agent (omp chosen, nothing open) at a project that has an entry, the tab opens and `omp -e <dir> --resume '<session>'` is typed. No self-test prompt: the check is skipped and says so. A person who pressed Invoke Agent or `+` first is not overridden. The id is checked (`[A-Za-z0-9-]`, 64 at most) at the BRP method and again in `plan_resuming`, because it is typed into a shell.
- **Scope, and what is not done.** Only omp: a custom command has no resume syntax the editor knows. A session that omp itself cannot find (its file deleted) is expected to show as an agent that never connects, so the entry would go after the 60 s with omp's own error left in the tab; that path is unit-tested (`resume_failed`) but I did not run omp against a missing session. The self test of a resumed session is not run, so a resumed agent shows `omp connected` and not `self test OK`.
- **Docs:** README (the new bullet, and the old "nothing starts" sentence qualified), `docs/guide/agents.md` ("Quit and come back").
