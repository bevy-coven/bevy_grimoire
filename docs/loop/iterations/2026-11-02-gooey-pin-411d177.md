## What the owner's interjection found, and the fix
**`wiggum@gooey` was running pass 82 with zero open issues anywhere in bevy_gooey.** Cause:
`wiggum@.service.d/zz-burn.conf` set `Restart=always`, which cannot tell a deliberate stop from a crash —
its 80th pass drained at 11:23:04 and systemd restarted it at 11:25:07. The watch script's 15-minute timer
never wins against the 2-minute `RestartSec`. The drop-in's own comment proved the intent was the
*failure* case.
- `zz-burn.conf`: `Restart=always` → **`on-failure`**; `wiggum.sh` now exits **1** when it gives up (was a
  bare `break`, i.e. 0) and **0** when it drains.
- **Proved with a probe unit**, not by reading: exit 0 → `ActiveState: inactive, NRestarts: 0`; exit 1 →
  `ActiveState: activating, NRestarts: 2`.
- Runbook rule added (`docs/loop/RUNNING-A-LOOP.md`), commit `5caa870`.
- Note: the 11:39:21 restart came from the unit instance started **before** `daemon-reload`; a running
  unit keeps the policy it started with. The instance from that point on carries `on-failure`.
