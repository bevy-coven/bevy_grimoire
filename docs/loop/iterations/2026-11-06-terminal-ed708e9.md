## Bugs found on the way
- The find box's keys first went to the field's hint: gooey puts `TextInputOf` on a text_input's field and its hint, and `hold_the_keyboard` took the first (seen live: the box open, its field empty). Fixed in 3824014 by asking for Bevy's `TextInput`; the test had shared the first lookup, so it agreed with the bug.
- The find box first hung its test forever: Escape in the box's gooey text field was read by gooey as "end the edit, then back", and the update blocked in `wait4` on a child process (the stack, taken under gdb as the test's parent, showed the test thread in `wait4`). Fix: Enter and Escape are decided in `PreUpdate` before Bevy's focused-input dispatch; on Escape the focus goes back to the body, whose observer stops the key, and that frame's keys are kept from the shell too (readline would read the next key as Meta).
- Shared target: another tree's build left a fingerprint newer than my edits, so cargo ran a `main` test binary (1,427 tests, without my module) as fresh. Touching the changed files before each run forced my own build.
