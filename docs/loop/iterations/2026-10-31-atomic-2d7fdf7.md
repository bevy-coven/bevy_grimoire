# 2026-10-31 io: every write of a project file is atomic, #199 (H2) of the hot-reload series

Focus: hot reloading (#198 → #204, the owner's override in `build-loop.md`) · Commits: 2d7fdf7 (+ review fixes and the docs commit) · Machine: laptop (edit, commit) + big (build, tests, clippy, gate) · Outcome: shipped

## Summary
`bevy_grimoire_core::atomic_file` is the one write path: a uniquely named hidden temp file beside the target, written, `sync_all`'d, renamed over the target (or hard-linked, for the no-replace write), then the directory flushed. 19 plain writes in the mapper (14 operations, the chooser's `kits.ron` and `vocab.ron`, the reference-image copy, the thumbnail and animation-bench caches) moved onto it, and `save_atomic` and `save_atomic_no_replace` are now wrappers. A ratchet fails on a new plain write.

## Baseline
Gate: green on main (bb0e7c5). `accept.py` not run: nothing it measures changed (no editor surface, no data format). Laptop load 6.9, free disk 60 GB; build, tests and gate ran on big (cold core build 37 s, cold mapper check 1 m 44 s, full `cargo test --workspace` 8 min on a cold target).

## Enhancement: #199 H2, atomic writes
Goal: no torn read and no half-written file after the writer dies, on every project file.
Files: `crates/bevy_grimoire_core/src/atomic_file.rs` (new), `ron_surgery.rs`, `lib.rs`, `live.rs` (a comment), 13 mapper source files, `docs/guide/reload-contract.md`.
What was already true: `save_atomic` renamed a temp file, so a reader never saw a torn map; `FileWatch` already skips dotfiles and non-`ron` names and settles for 0.5 s, so a rename-replace was already one reload. What was not: one fixed `<path>.tmp` (two writers of one path collided and the second was refused with ENOENT), no flush, and 21 `fs::write`/`fs::copy` sites that truncated the target in place.
Proof, on big in a scratch clone:
- Base commit, new tests applied: `two_writers_of_one_path_do_not_corrupt_each_other` fails with `ron: .../town.map.ron: No such file or directory (os error 2)`; the ratchet fails with 25 flagged lines (the 21 writes and copies plus 4 rename/link lines of the old tmp code).
- Base commit, the reader, kill, names and watch tests pass: they pin what `save_atomic` already did, so they are not failing-first. Control instead: with `put` mutated to a plain `fs::write`, five of seven fail (a reader saw a 0-byte file; the killed writer left 1,028,096 of 2,097,152 bytes; a reader saw a mix of two writers).
- After: 7 + 7 + 3 tests pass; `cargo test --workspace` passes (exit 0).
What is claimed is what is tested. **Durability against power loss is not claimed.** On macOS Rust's `File::sync_all` is `F_FULLFSYNC`: measured on APFS 6.4 ms against 0.1 ms for `fsync`, 14 ms per write with the directory flush. The 10,000-replacement test therefore uses `write_cache` (no flushes), and a 300-replacement test covers the flushed path. Caches use `write_cache` too.
MCP: no operation added or changed; a write now creates its parent directory (the old plain write refused when it was missing), which every call site already guaranteed.

## Review
A `reviewer` subagent ran over 2d7fdf7 (7.5 min). No must-fix. Fixed in the follow-up commit:
- The ratchet cut each file at its first `#[cfg(test)] mod` and skipped thousands of production lines after it (`chooser.rs` from line 2625, `editor.rs` 13598, `tiles.rs` 3479, `compose.rs` 2722). It now cuts exactly each test item by its own extent, with a self-test; the whole production source is scanned and finds nothing more.
- The kill test leaked an endless writer child when an assertion failed first: the child is killed on drop. The reader, looker and kill tests no longer depend on timing (the writer goes on until the reader has overlapped).
- The stale-temp sweep matched `town.map.ron.bak`'s temp files for `town.map.ron`: it now matches `<digits>-<digits>.tmp` exactly, with a test. `write_cache` does not sweep (a thumbnail directory is large).
- Docs overclaimed the ratchet and the 10,000-replacement run; both corrected. A stale comment in `live.rs` fixed.
Noted, not changed: a symlinked target is replaced by a file instead of written through (maps already behaved so); a read-only target is now replaced; a map name near 235 bytes would hit `ENAMETOOLONG` with the longer temp name; `editor.rs`'s reference copy is check-then-write (pre-existing; `write_new` would fit).
