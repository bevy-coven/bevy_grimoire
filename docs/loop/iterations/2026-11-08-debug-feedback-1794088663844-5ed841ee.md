## Oracle: `spec`

"We should only have an agent panel" is a requirement about what controls exist, so it is an invariant on one run: while the pane invites the agent (an agent chosen, nothing open) the bar has no `Agent` chip, and once a tab is open the chip is there to add another. ## The fix, prepared and unproven

`crates/bevy_cauldron/src/terminal_pane.rs`: `offers_another_agent(&Terminal)` is `terminal.agent() != Off && !terminal.invites_the_agent()`, and the bar draws the `Agent` chip only when it is true. A unit test (`the_agent_chip_is_not_a_second_door_to_the_empty_panes_button`) and `tests/capture_feedback_1794088663844.rs` (three tests through `harness::build_headless`: the empty pane has the button and no chip; the chip comes with the first tab and goes when the last is closed; a plain shell beside the chosen agent gets the chip) are written. **None has been compiled or run**, so there is no failing run to quote and no passing one. They are on the parked branch, last, so the docs commits can be taken without them.
