## The relation, and why

**Invariance of the size class.** Segura, Fraser, Sánchez & Ruiz-Cortés, *A Survey on Metamorphic Testing*
(`10.1109/TSE.2016.2532875`): the effective relations are those "strongly inspired by the semantics of the
program under test". The bar's semantics are stated by the code — `label_the_primary_group` gives the tools
their names "because a 16 px picture is a guess until it has been learned" and leaves "the rest of the bar
(undo, save, view)" as pictures. So a button's width says which class it belongs to, and a button from one
class standing in the other's run is exactly what a person reads as "out of place".

The survey's other finding is why this is measured rather than read off the code: a relation close to the
implementation — "the labelled set contains Fill" — **passes on the defect**, and that membership is in fact
deliberate (`LABELLED_BUTTON`, #302). What was wrong was the button's *position*, which only the laid-out
widths can show.

## The cause

A spawn order, contradicting a decision the same file already records. `LABELLED_BUTTON`'s doc calls Fill
*"the command whose button carries a word under its icon besides the tool modes: Fill, which the brush's own
row of tools stands beside"* — and `spawn_toolbar` spawned it from the command loop that draws the pictures,
because it is a one-shot command rather than a mode. Both facts are true and they conflict: Fill **is** a
one-shot command (`toolbar.rs`'s header: "a one-shot flood from the cursor, not a mode", so a lit Fill would
claim a mode the editor does not have) and it **is** a worded button.

## The fix

Fill moves; it does not change. Still a `ToolbarCommand`, still not a group option, `label_the_primary_group`
untouched — spawned once **before** the separator instead of inside the pictures' run, and skipped by that
loop so it cannot appear twice.

## Proof

- the whole-application test fails on the base commit (above) and passes on the fix;
- the capture's own platform, a fixed build on `mac_air`: Fill measures 107 physical px at `x 627..733`,
  immediately after Run (91), inside the worded run, with the pictures following at a uniform 65-66;
- `cargo clippy -p bevy_cauldron --all-targets -- -D warnings` clean;
- the bar's own tests stay green, including `the_fill_tooltip_is_centred_on_the_fill_button` — the tooltip
  still lands on its button after the move.
