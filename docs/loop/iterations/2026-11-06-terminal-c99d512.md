# 2026-11-06 terminal: three steps toward VS Code's terminal — a lean output path, drawn grounds and selection, rows that fit

Focus: the embedded terminal (the owner's ask for this pass) · Commits: f89e1df (code, swept in by a concurrent pass), 0285649..c99d512 · Machine: big · Outcome: shipped

## Summary
The owner asked for a VS Code-grade terminal, one step at a time. The terminal already existed (alacritty_terminal + a PTY, docked by Ctrl+`), so this pass measured it and fixed the three things that measured wrong: per-call allocation and per-frame row copies on the output path (#308), cell backgrounds and the selection never drawn — inverse text invisible (#309), and every row drawn 20 % too tall at the editor's UiScale, so the prompt fell off the pane (#310).

## Baseline
Gate: green on main at 42b0e85. `accept.py`: not run (no editor-surface operation changed; the terminal is not in its scope). Load 0.46, free disk 296 GB, available RAM 18 GB.

## Bugs fixed
### #308: the output path allocated a grid per feed and copied every row per frame
Must-fix: blocks n, common y (every keystroke echo), no workaround y. The issue's first claim — a `yes` flood freezes the editor — was **falsified**: a test written to fail on it passed on the old code; measured 21–62 KB per drain in < 1 ms (issue comment). Recorded, not deleted.
Root cause: `feed` swapped in a fresh `Term` around each parse; `draw_the_terminal` cloned all rows twice a frame. · Regression check: `terminal::flow_tests::*` (3); 1000 one-byte feeds 35 ms → 21 µs.

### #309: inverse text, coloured backgrounds and the selection were never drawn
Must-fix: blocks y (TUIs' highlighted rows unreadable), common y, no workaround y.
Root cause: `colour_runs` split rows on ink only and never set a ground; `rebuild` never read the selection. · Regression check: `the_terminal_paints_grounds_and_the_selection::*` (failed before: `ink: Srgba(0.115, 0.107, 0.093), ground: None`).

### #310: rows 20 % too tall at UiScale 1.2
Must-fix: blocks y (prompt clipped after a screenful), common y, no workaround y.
Root cause: rows got `Val::Px(physical height)`, which Bevy scales again. · Regression check: `the_terminal_rows_fit_the_pane_at_the_editors_scale::*` (failed before: "last row ends at y = 725 px, below the body's bottom at 690 px").
