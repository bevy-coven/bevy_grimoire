# The bevy_emerge MCP tools

Generated from the server's own tool declarations. **Do not edit this file** — it is written by `cargo run -p bevy_emerge_mcp -- --emit-docs`, and a test fails when it does not match the server.

The server speaks the Model Context Protocol over **stdio**, and reaches the running editor over the Bevy Remote Protocol on `BEVY_BRP_PORT` (default 15702). It writes nothing to disk itself: the editor owns the project directory, and every file the editor writes is written by the editor.

## The tools

### `emerge_present`

Put a result in front of the person: a title, a one-paragraph summary, what they specified, what you inferred, up to three places worth checking, and the operation ids it covers. The editor shows it as a question: Keep, or Undo all (which undoes every listed operation, newest first). This call returns at once; read the person's answer from emerge_state's presentation.answer ("kept", "undone", or why the undo stopped). It does not change the map by itself.

| annotation | value |
|---|---|
| `readOnlyHint` | false |
| `destructiveHint` | false |
| `idempotentHint` | false |

### `emerge_list_operations`

Every operation the running bevy_emerge editor knows, with each one's parameters' JSON schema and how it is undone. Call this before emerge_apply_operation so the parameters are the ones the operation actually takes. Returns the list; it does not change anything. The undo column names the strategy an operation declares; emerge_undo_operation performs it.

| annotation | value |
|---|---|
| `readOnlyHint` | true |
| `destructiveHint` | false |
| `idempotentHint` | true |

### `emerge_preview_operation`

What an operation would change, and nothing changed: the map, the data file and the operation log are all left alone. Use this to check a proposal before applying it. Returns what would change, or the refusal.

| annotation | value |
|---|---|
| `readOnlyHint` | true |
| `destructiveHint` | false |
| `idempotentHint` | true |

### `emerge_apply_operation`

Run one of the editor's operations. Changes the editor (most operations change the open map and write its file; brush_arm only arms a piece) and appends a line to the operation log. Set dry_run to true to see what would change without changing it. Returns the operation's id, which can be cited in a report to the developer, and the log's own record of it. When the operation changes a document and a map is open, the answer's checks field names the edge faults and overlapping placements the change introduced (new, at most 20 of each) with new_total, and each kind's total on the whole map; it is null otherwise. The operation replaces the values it names rather than adding to them, so it is marked destructive. Take a change back with emerge_undo_operation and the returned id.

| annotation | value |
|---|---|
| `readOnlyHint` | false |
| `destructiveHint` | true |
| `idempotentHint` | false |

### `emerge_undo_operation`

Take back one change made through emerge_apply_operation. Pass operation_id, the id that call returned; omit it to take back the newest change that has not been taken back. The editor applies the inverse the change recorded, writes the data file, and appends a new log line naming the line it undoes; the log is never edited. Refuses, and changes nothing, when the change was already undone, when a newer change exists (the answer names it; undo that one first), when the map was changed outside the log since (a hand-edited file, the menu, or another map open; the answer names what differs), or when the change recorded no inverse. Undoing an undo puts the change back, and the change's own id takes it back again. Set dry_run to true to see what the undo would set. Returns the undo's own operation id and what it set.

| annotation | value |
|---|---|
| `readOnlyHint` | false |
| `destructiveHint` | true |
| `idempotentHint` | false |

### `emerge_state`

What the editor is holding right now: the open map and its bounds, how many pieces it has, what is armed, what is selected, which door and tab are open, and what the editor last said and what has gone wrong. The editor section also names the next undo and redo (undo_next, redo_next) and how many are stacked (undo_depth, redo_depth). The map section names up to 50 pinned placements by id and reason (pinned). pinned_total is the full count; past 50, pass pinned_from (from pinned_next) to read the rest. Returns that summary as JSON, and changes nothing. Call it before a change to know what you are changing, and after one to check that it landed.

| annotation | value |
|---|---|
| `readOnlyHint` | true |
| `destructiveHint` | false |
| `idempotentHint` | true |

### `emerge_list_pieces`

The library's pieces, a page at a time. Each row carries the piece's id, the mesh it is drawn with (null for a flat footprint marker), its kind, effects and looks, and its labels: who labelled each axis (model, agent or human), the record's model, date and confidence. Filters combine: with_mesh, unlabelled, by_model, confidence (high, medium or low), id_contains. total is the true count after the filters. A page holds 50 rows; past 50, pass pieces_from (from pieces_next) to read the rest, and how_to_narrow names the filters when a filtered page is still capped. Refuses when no project is open, rather than answering an empty list. Returns that page as JSON, and changes nothing.

| annotation | value |
|---|---|
| `readOnlyHint` | true |
| `destructiveHint` | false |
| `idempotentHint` | true |

### `emerge_capture_still`

A picture of the editor as it is now -- the world and the interface, because the editor draws both into one image -- plus a state summary of the same moment. The picture is returned as an image and written to a file whose path is in the answer. The answer also carries a fingerprint of the picture's bytes: two stills with the same fingerprint are the same picture, so compare fingerprints rather than file paths to tell whether the screen changed. Use this after a change to see what it did, or before one to see what it was like.

| annotation | value |
|---|---|
| `readOnlyHint` | false |
| `destructiveHint` | false |
| `idempotentHint` | false |

### `emerge_snip`

A rectangle of the editor's picture, cut out and returned as an image. rect is [x0, y0, x1, y1] in window pixels, origin at the top left, x1 and y1 exclusive, so the same pixels a still is in. The crop is written to a file whose path is in the answer, with the state of the same moment. It writes one crop file under target/loop and changes no map data: it is not an operation, not logged and not undoable. Refuses, and writes nothing, on a rectangle that is empty, reversed, negative or outside the picture, and says the picture's size. Use it to look closer at one part of a still from emerge_capture_still.

| annotation | value |
|---|---|
| `readOnlyHint` | false |
| `destructiveHint` | false |
| `idempotentHint` | false |

### `emerge_list_snips`

The snips the person took in the editor, newest first: each one's name, when it was taken, the map and the active tool, the note the person typed, the rectangle in window and picture pixels, the camera view, the cursor's world position and the placements inside the rectangle. Each entry names its picture file, and the newest picture comes back as an image. It reads files the editor wrote, so it needs no editor running and changes nothing. Returns how many snips there are, how many are shown, the snips still being saved (pending: confirmed in the editor, picture not yet written, so not yet in the snips list) and each .json file in the snips folder that is not a snip record or has no picture file, with the reason.

| annotation | value |
|---|---|
| `readOnlyHint` | true |
| `destructiveHint` | false |
| `idempotentHint` | true |

### `emerge_capture_sequence`

A sequence of frames of the editor, with an optional operation applied once the first frame is in -- so frame 0 is the state before the action and the later frames are what it did. The frames are written to a directory and their paths are in the answer. The editor takes the frames, so the timing does not depend on this server's round trips. The rate is two to fifteen frames a second. A frame is asked for only once the one before it is written, so a stalled editor delays the frames after it rather than losing them; a frame that does not land within five seconds ends the run with a reason, and the status is done only when every frame is written. The call waits for the run to end, for at most the sequence's length plus five seconds a frame and a margin.

| annotation | value |
|---|---|
| `readOnlyHint` | false |
| `destructiveHint` | true |
| `idempotentHint` | false |

### `emerge_read_oplog`

The editor's operation log, newest last. Every operation appends one line, whether a person or an agent did it. Read it to see what has been done to this project. A refusal is not logged, so a line here is a line about a change that happened. An undo is a new line naming the line it undoes.

| annotation | value |
|---|---|
| `readOnlyHint` | true |
| `destructiveHint` | false |
| `idempotentHint` | true |

### `emerge_frame_view`

Frame the editor's Map camera on a box. target: "map" (the whole map), "selection" (the locked placement; refused when nothing is locked), {"placements": [ids]} (their union), or {"rect": [x0, z0, x1, z1]} (map metres). It only moves the camera: it never changes map data, is not logged or undoable, and is not an operation. Refuses, and moves nothing, on an unknown id, an empty selection or a flat rectangle. Returns what was framed, the focus and the view height in metres. Call emerge_capture_still afterwards to see the result.

| annotation | value |
|---|---|
| `readOnlyHint` | false |
| `destructiveHint` | false |
| `idempotentHint` | true |

## How the two paths converge

Every operation writes the data file, and the editor watches that file. So:

- an **agent** calls `emerge_apply_operation`, the editor writes the file, and the editor's own state is already the new one;
- a **person** edits the file in a text editor, the watcher notices within a quarter of a second, and the editor re-reads it — **and keeps what it had if the file does not parse**;
- a **person at the keyboard** uses the editor's own controls, which dispatch the same operations.

The measured latency of both paths is in the iteration report.
