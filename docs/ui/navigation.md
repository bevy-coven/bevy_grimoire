# Getting around, as it is now

Measured against `navigation-baseline.md`, which is frozen as NV-01 (#378) left it (`the_navigation_baseline_stays_frozen`).

Generated by `crates/bevy_cauldron/tests/navigation.rs` (`navigation::`), which drives the editor from a
cold start on a fixture project by the keys and pointer actions a person uses. The test **checks** this
file: it fails when the table below and the editor disagree, and rewrites it only with
`UPDATE_NAVIGATION_BASELINE=1`:

```
UPDATE_NAVIGATION_BASELINE=1 cargo nextest run -p bevy_cauldron --test editor -E 'test(navigation::)'
```

**One press is one key event.** A chord is one press (`Cmd+O` counts once) and a typed character is
one. Pointer actions — a click, a wheel notch — are counted in their own column, because a route
that needs the wheel has no keyboard form at all. A row's route is the driver's own record of what it
did, in order.

## What a later change is held to

- Any workspace in **1 press**: a destination of the workspace kind is *met* when it arrives in at most one press and no pointer action.
- Any named thing in at most **Cmd+P, its name and Enter** — one press, some typing, one press: *met* when the finder is **driven** with the
  thing's name (`Cmd+P`, the characters, `Enter`) on a project that holds one — a piece, a placed piece, a lattice, a composition, a registered
  data file and a note — and arrives at its page. The cost shown is that route's presses.
- Back to where you were in **1 press**: held by `back_and_forward_across_workspaces`, not a row here.
- **Never worse than the baseline**: a destination that arrived then still arrives, and costs no more keys and pointer actions together.

A target that is *missed* is filed as its own issue, naming the destination and the route; the issue is cited in the Target column and
the test fails for a miss with none.

## What the numbers say

1 of 20 destinations cannot be reached at all. Of the 19 that can, 2 are where the editor already starts, 10 are reached by keys alone, and 7 need the pointer. The inspector moves only by the wheel, so scrolling to a heading costs between 1 and 2 notches. Set against that, a workspace model asks for any workspace in one press, any named thing in at most `Cmd+P`, its name and `Enter`, and one press back: 1 of these 19 cost more than one press and 7 of them need the pointer.
