# Getting around, as it is now

The baseline this is measured against is `navigation-baseline.md`, frozen as NV-01 (#378) left it.

Generated by `crates/bevy_cauldron/tests/navigation.rs` (`navigation::`), which drives the editor from a
cold start on a fixture project by the keys and pointer actions a person uses. The test **checks** this
file: it fails when the table below and the editor disagree, and rewrites it only with
`UPDATE_NAVIGATION_BASELINE=1`:

```
UPDATE_NAVIGATION_BASELINE=1 cargo nextest run -p bevy_cauldron --test editor -E 'test(navigation::)'
```

**One press is one key event.** A chord is one press (`Cmd+O` counts once) and a typed character is
one. Pointer actions — a click, a wheel notch — are counted in their own column, because a route
that needs the wheel has no keyboard form at all. A row's route is the driver's own record of what it
did, in order.

## What a later change is held to

- Any workspace in **1 press**.
- Any named thing in at most **Cmd+P, its name and Enter** — one press, some typing, one press.
- Back to where you were in **1 press**.

## What the numbers say

6 of 20 destinations cannot be reached at all. Of the 14 that can, 2 are where the editor already starts, 3 are reached by keys alone, and 9 need the pointer. The inspector moves only by the wheel, so scrolling to a heading costs between 5 and 7 notches. Set against that, a workspace model asks for any workspace in one press, any named thing in at most `Cmd+P`, its name and `Enter`, and one press back: 1 of these 14 cost more than one press and 9 of them need the pointer.
